# 控制目標、可調安全參數與原HA危險門檻

> 2026-11-03 使用者確認的設計方向；**尚未實作**。本次只更新規範/追蹤，不改P1參數、控制程式或原HA。規範主入口見 [DEVELOPMENT_SPEC.md](DEVELOPMENT_SPEC.md)。

## 1. 水質控制目標已確認（D01）

- pH/EC使用設定上下限的平均值作停止繼續投藥的目標，不採「必須到區間另一端才停止」或另換未經核准演算法。
- 加養使EC上升，讀值達到或高於平均目標就不再發新加養脈衝；加酸使pH下降，讀值達到或低於平均目標就不再發新加酸脈衝。讀值已在不需投藥一側時不得為追逐目標繼續投藥。
- 使用者指出感測反應慢於真實變化；控制採保守脈衝、必要混合/採樣等待、有效新讀值後再評估，不因前次藥劑尚未反映而連續追加。原子取消後續脈衝及劑量/期限限制仍需驗證。
- 最高原則是避免過量及超出界限：EC防止過高，加酸另須防止pH過低，不把「避免超過上限」錯寫成只有pH高標保護。
- 停止繼續投藥不等於立刻宣告階段完成或可灌溉；仍需有效混合/穩定及完整品質確認。不能保證感測落後時物理上完全零過衝，也不以濾波/延遲掩蓋危險讀值。
- 目標由使用者可調的上下限推導，前台顯示唯讀計算結果，不新增另一組可寫目標與上下限互相矛盾。現行預設對應pH目標5.6、EC目標0.85mS/cm；P1僅監測區間，不因此變成已實作控制。

## 2. 已有參數與不足：可調，不要求現在逐項人工決定

原系統Helpers及P1原生Numbers已提供液位/pH/EC上下限、補水/加養/加酸逾時與獨立攪拌時間。P1亦有原生Options的來源有效期限設定。新整合沿用前台可調能力，使用integration-owned Number/Options，不要求另外手建同名input_number或寫死在程式。

但並非所有原控制常數都有Helper，也不能用目標上下限代替全部安全限制：

| 參數群組 | 現況/缺口 | 規範要求 |
|---|---|---|
| 補水低高標、pH/EC目標上下限 | 原Helpers/P1已有 | 繼續前台可調，品質區間與平均控制目標分離 |
| 補水/加養/加酸逾時、獨立攪拌時間 | P1已有時間Number | 繼續可調；階段、跟隨與整輪總期限的語意不能混用 |
| 加藥最低安全液位 | 原跟隨加養門檻1.2m在規則，不是獨立安全Helper | 暴露明確參數與用途；跟隨門檻不等於所有槽/所有加藥的安全水位，不能默默泛化 |
| 酸/養脈衝及關閉確認 | 原入口名稱10/45秒，確認12/92秒，多為規則/裝置常數 | 需提供可調控制參數並驗證輸出能力；投藥時長、確認期限與設備端定時分開 |
| 加藥後混合/採樣等待、穩定次數/間隔 | 原多為5分鐘、8次的規則常數；不是P1獨立攪拌時間Number | 提供原生可調參數，invalid不計成功，不能依未反映前次投藥的舊值續加 |
| 單輪/單階段累積加藥上限及整輪總期限 | 現有Helpers/Numbers沒有完整獨立限制 | 新增有限的可調上限；先可用累積ON時間/脈衝次數，未校正流量時不捏造mL；不能默認無限制 |
| 農藝危險門檻與持續時間 | 原多寫在規則、與品質目標Helper分離 | 新增原生Number/設定，預設採原HA實際判斷值，見下一節 |

原值存在的項目應標示來源與適用語意；除了使用者已明確指定的平均控制策略與危險預設，其餘脈衝/期限等完整schema及跨參數關係仍由對應工程項目凍結，不再要求使用者現在逐項給定固定數字。原本不存在的累積上限/流量值不得偽稱來自原HA。

設定需做單位、範圍、跨欄位、有限值與設備能力驗證；收緊安全界限即時生效，不能透過設為0/極端值關閉保護。P1現有寬輸入範圍不是物理安全認證，不在本次文件更新偷偷改值。

## 3. 危險門檻已確認採原值、全部前台可調

依已記錄原HA實際條件（FUNCTIONAL_PARITY_REVIEW F21），不是通知文字：

| 設定 | 原HA預設判斷 | 必須保留的區分 |
|---|---|---|
| pH危險低標 | pH < 3.8 | 與品質目標下限分開；不是只要pH>3.8就可灌溉 |
| EC危險高標 | EC > 1.3 mS/cm | 原通知曾寫1.5，但實際規則為1.3；新訊息從同一權威設定產生 |
| pH高值告警 | pH > 6.8，持續10分鐘 | 門檻與持續時間分別可調；原來是告警條件，不能無聲升級成所有動作的急停門檻 |

原低pH/高EC的「每10分鐘/對應泵開事件檢查」不是「必須持續10分鐘才保護」；不得混用。新整合沿既定設計採後端事件/有效性評估、停泵後異常仍可告警，不複製只有泵ON才看見異常、錯誤急停呼叫或通知文字不一致等缺陷。

使用者指定採原值的是初始預設，不是不可調常數，也不是通用農藝安全背書。既有設定/將來已保存的使用者值不能在升級或重載時被出廠預設覆蓋。沒有原始依據的其他危險值不虛構。

## 4. 非Helper可以取代的事項

前台可調解決參數設定，不等於實際硬體具備保護。泵的直接/定時別名、設備能否採用所選脈衝、斷線/HA停止時最大ON保護，仍須透過設備能力與實測驗證。這是工程驗證/啟用前設定，不是要求使用者現在另外決定一套控制演算法。

## 5. 驗收要求

- EC上升/pH下降的中點停止方向正確；達標後無新脈衝，已送出I/O的停止/確認行為明示。
- 慢回報、連續舊值、invalid、混合等待與上限不會產生無界追加；停止加藥與穩定完成分開。
- 原生UI與Card同源調參，保存/取消及重開一致；跨欄位非法設定無半套寫入。
- 危險預設與原條件相同，EC告警文字不再錯寫1.5；高pH持續時間與其他檢查週期不混用。
- 修改後的使用者值正常持久保存，重載/升級不被原HA預設覆蓋；原站不因本規範而改值。
