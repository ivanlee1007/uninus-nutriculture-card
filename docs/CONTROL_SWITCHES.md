# 總開關、階段子開關與流程組合契約

> 狀態：已納入產品設計，安排 P2 建立控制骨架、P3 完整接入各階段；**尚未實作**。P1 仍為影子監測，沒有這些 Switch 或任何設備控制。本文件不授權部署或操作原農場。

## 1. 目的與原系統對應

保留使用者以開關調整補水、加養、加酸、攪拌組合的能力。原系統有四個「自動化啟用／停用」入口，另有四個「啟動流程旗標」，兩者不能混為一談；「階段鏈結」只決定連動，也不是整套系統總開關。本次重新檢查未發現獨立且一致攔截所有流程的總開關，故總開關屬明確新增功能。

## 2. 權威設定與原生 Entity

每槽由 integration 管理以下持久設定，透過原生 Switch Entities 與配套 Card 操作同一份後端設定。名稱為語意 key，不保證 Entity ID 由槽名拼接；身份仍依 config entry 與穩定 unique ID。

| key | 顯示用途 | 關閉效果 |
|---|---|---|
| `automation_enabled` | 水養液自動化總開關 | 禁止本整合所有新控制啟動，安全停止本槽擁有的控制流程 |
| `refill_enabled` | 補水階段 | 不納入補水；執行中停用則中止該階段及其後續工作 |
| `nutrient_enabled` | 加養階段 | 不納入加養；執行中停用則禁止後續脈衝並停止該階段 |
| `acid_enabled` | 加酸階段 | 不納入加酸；執行中停用則禁止後續脈衝並停止該階段 |
| `mix_enabled` | 獨立／最終攪拌階段 | 不納入獨立／最終攪拌；不等同取消加藥必需的循環安全前提 |
| `stage_link` | 階段鏈結 | 不允許自動跟隨或完成後串接下一階段；僅執行明確指定的單階段 |

`stage_link` 是上述五個開關之外的獨立設定，不能以總開關取代。初次建立、舊設定遷移與重新安裝都不得自動啟用實體控制：總開關預設 OFF；首次啟用前明確選擇子階段、完成輸出／來源及安全驗證。不可把舊「啟動旗標為 on」解讀成持久啟用同意。

P2 必須定義全部階段的資料模型與操作語意；尚未實作的 P3 階段在原生 Entity／Card 顯示 unavailable 或「尚未支援」，拒絕啟用及啟動，不提供可誤認已生效的空開關。P3 再逐項開放已通過驗收的階段。

## 3. 總開關語意

### 關閉

1. 先阻擋新的整輪、單階段、排程、自動跟隨及重試開啟命令；所有入口使用相同後端 gate。
2. 撤銷舊任務世代，取消尚未執行的脈衝、等待、Timer、延遲及重試。已送出 I/O 不宣稱能回滾，轉入安全停止及回饋確認。
3. 只停止本槽明確擁有的輸出，完成共用輸出仲裁，不觸碰其他槽或原有外部自動化。
4. 停止過程顯示 `stopping`；輸出未確認關閉時必須保留故障／未知提示，不能只因設定已 OFF 就宣稱設備已安全停止。
5. 保留子開關、鏈結、參數、配方與排程定義。排程定義不刪除，僅禁止停用期間執行或事後補跑。
6. 監測、品質診斷、參數編輯及安全告警仍可使用；總開關關閉不等於卸載整合或消除故障。

### 開啟

- 只恢復「允許啟動」，不立即開啟任何馬達，不恢復被中止的加藥／等待任務，不補跑錯過的排程。
- 原子檢查當下設定、急停／故障狀態、階段可用性與必要感測器／輸出；不得自動清除急停。
- 之後明確啟動或未來有效排程到時才可運行。
- 關閉總開關不得覆寫任何子開關；再開啟須維持原有組合。

## 4. 子開關與組合

- 啟動前依已啟用階段形成可執行集合；停用者標示 `skipped_disabled`，不是 `completed`、成功達標或故障。
- 支援全部開啟、只補水、補水＋加酸＋攪拌、只加養／加酸等組合，但每個階段仍檢查安全前提。任一組合不合法時須具體說明原因，不默默啟用被使用者關閉的階段。
- 全部子開關 OFF 時可以保留設定，但不啟動控制；顯示「未選擇任何階段」。
- **執行中停用**：立即拒絕該階段後續物理開啟並取消其工作，確認其輸出停止；不能等下一輪才生效。共用循環馬達僅在沒有其他合法所有者需要時關閉。安全相依的其他階段應停止或進入明確安全收尾，不可繼續盲目加藥。
- 執行中停用階段後，預設中止本輪的自動接續，待使用者明確重新啟動按新組合評估；不以被中止階段冒充完成。若未來要支援不中斷本輪的動態重組，須先補決策與相依圖測試，不能默認已支援。
- 執行中重新啟用子開關不自動重啟被中止工作；新請求重新驗證最新設定。

## 5. 鏈結、整輪與單階段

- `stage_link=ON`：允許在可執行集合內依安全相依圖自動接續，並允許明確設定的補水／加養跟隨重疊。不能把原本跟隨設計簡化成四階段永遠串行。
- `stage_link=OFF`：禁止自動接續及跟隨；使用者只能明確啟動單階段。「啟動整輪」需提示開啟鏈結或改選單階段，不能暗中變成不同流程。
- 「單階段啟動」明確表示不隱含接續；總開關、該階段子開關及安全 gate 仍須通過。原啟動旗標的手動／連動意義必須在遷移時明確對應，不能只改 Entity 名稱。
- 排程須標明執行整輪或單階段，不直接控制馬達。現有每日補水排程的連動選擇於遷移預覽中展示。
- 這些是語意操作；實際服務名稱及版本化 transport 於 P2 實作前凍結，不在本文件宣稱現有服務已存在。

## 6. 安全限制與備妥判定

- 關閉補水不代表允許低液位加藥；不滿足安全液位時拒絕加養／加酸，而不是擅自補水。
- 關閉「獨立／最終攪拌階段」不等於取消加藥所需最低循環、混合與採樣等待。必要混合無法滿足時拒絕加藥，明示相依原因；不得用顯示層繞過。
- 品質在區間、流程完成與允許灌溉為不同結果。略過、停用、中止、讀值過期或故障不能自行轉為養液備妥。
- 總開關是正常停用，不是緊急停止。急停為鎖定保護；復歸與重新啟動分開，開啟總開關／子開關不能解除急停。
- 即使總開關 OFF 或階段停用，與本槽相關的設備失敗／輸出仍開啟警告不能被隱藏。外部手動繼電器或其他 HA 自動化不受本整合總開關直接封鎖；遷移須消除雙重控制，並明示無法控制的外部行為。

## 7. Card 與原生前台

- 同時呈現總開關、四個子開關、鏈結及有效流程組合預覽，不能只用顏色表示。
- 啟用設定、啟動一次、停止本輪、緊急停止、復歸是不同控制。前台不能把 Switch toggle 當作一次性啟動。
- 顯示每階段 `disabled`／`skipped_disabled`／`running`／`completed`／`aborted`／`fault`；停止請求與物理停止確認分開顯示。
- 保存與操作結果由後端讀回；取消 UI 編輯不得改後端；切槽、斷線、舊回應不能把操作送到另一槽。
- 原生 HA、Card、排程及服務操作共用 gate；Card 不直接呼叫底層馬達服務，不能在瀏覽器擁有流程計時器。
- P1 schema v1 與 shadow-only Card 保持不變。P2 控制能力須使用明確版本化／能力宣告，舊 Card 對未支援控制契約繼續 fail closed；不能在本次文件更新偷偷擴張已發布 P1 的可控能力。

## 8. 必要驗收案例

| 編號 | 必須驗證 |
|---|---|
| C01 | 初次設定／遷移不致動；未支援階段不可啟用 |
| C02 | 總開關 OFF 阻擋原生、Card、單階段、整輪、排程及跟隨等所有入口 |
| C03 | 總開關 OFF 發生在脈衝／等待／重試／已排隊請求時，舊工作不能重新開輸出 |
| C04 | 關閉總開關後保留四子開關與鏈結；重啟 HA／重新開啟不續跑、不中途補藥 |
| C05 | 四子開關的每一組合都能解析，停用階段明確略過；全 OFF 不運行 |
| C06 | 執行中關閉各階段即時中止；停止未確認必須故障可見；重新啟用不恢復舊任務 |
| C07 | 只補水、略過加養、只酸度調整等單獨與組合路徑，安全前提不足有明確拒絕 |
| C08 | 關閉獨立攪拌不能繞過加藥必需的循環／混合；共用輸出不被另一階段誤關 |
| C09 | 鏈結 OFF 不串接／不跟隨；ON 可按相依圖跳過停用階段並支援合法重疊 |
| C10 | 子階段停用／中止不等於水質合格或可灌溉 |
| C11 | 急停／復歸與總開關獨立；切換啟用不清故障、不自動開馬達 |
| C12 | 原生與 Card 狀態一致，失敗保留真實狀態；雙擊、跨槽、舊回應不得錯寫 |
| C13 | 相同物理輸出之直接／定時 Entity 別名先確認對應並統一仲裁；不同槽不互相接管 |
| C14 | 外部控制或原自動化仍能干預時明確揭露；沒有將新總開關誇稱原站全域急停 |

C01–C04、C06、C11–C14 先由 P2 奠定與補水驗證；涉及加養／加酸／混合的 C05–C10 在 P3 完整驗收；排程與舊系統相容在 P4 驗收。新增控制不得改動原農場，除非另外取得明確部署／接管授權。
