# 總開關、階段子開關與流程組合契約

> 最新定案：取消獨立stage_link；各階段實際開始前檢查星期；增加原生整輪運行Switch並保留start_flow。以[已確認控制決策](CONTROL_DECISIONS.md)為準；尚未實作，P1不變。

> 狀態：已納入產品設計，安排 P2 建立控制骨架、P3 完整接入各階段；**尚未實作**。P1 仍為影子監測，沒有這些 Switch 或任何設備控制。本文件不授權部署或操作原農場。流程/UI依據見 [FLOW_DESIGN_RESEARCH.md](FLOW_DESIGN_RESEARCH.md)；R01與R03評估時點已確認；R02/R04等細節仍待確認，Switch執行契約見已確認決策文件。

## 1. 目的與原系統對應

保留使用者以開關調整補水、加養、加酸、攪拌組合的能力。原系統有四個「自動化啟用／停用」入口，另有四個「啟動流程旗標」，兩者不能混為一談；「階段鏈結」只決定連動，也不是整套系統總開關。本次重新檢查未發現獨立且一致攔截所有流程的總開關，故總開關屬明確新增功能。

## 2. 權威設定與原生 Entity

每槽由 integration 管理以下啟用設定與運行Entity（flow_run不是持久控制許可），透過原生 Switch Entities 與配套 Card 操作同一份後端設定。名稱為語意 key，不保證 Entity ID 由槽名拼接；身份仍依 config entry 與穩定 unique ID。

| key | 顯示用途 | 關閉效果 |
|---|---|---|
| `automation_enabled` | 水養液自動化總開關 | 禁止本整合所有新控制啟動，安全停止本槽擁有的控制流程 |
| `refill_enabled` | 補水階段 | 不納入補水；執行中停用則中止該階段及其後續工作 |
| `nutrient_enabled` | 加養階段 | 不納入加養；執行中停用則禁止後續脈衝並停止該階段 |
| `acid_enabled` | 加酸階段 | 不納入加酸；執行中停用則禁止後續脈衝並停止該階段 |
| `mix_enabled` | 獨立／最終攪拌階段 | 不納入獨立／最終攪拌；不等同取消加藥必需的循環安全前提 |
| `flow_run` | 整輪流程運行Switch（新增） | ON請求啟動整輪；OFF正常停止本輪，不修改總/子開關；結束自動OFF，外部服務啟動亦同步狀態 |

確定保留總＋四子開關，取消獨立stage_link及額外多階段許可；接續由已保存編排決定。另有整輪運行Switch，不能與總開關混淆：總ON只允許控制，flow_run ON才請求一次整輪。初次建立/遷移總開關預設OFF；舊啟動旗標on不代表控制同意，需驗證來源/輸出/安全。

P2 必須定義全部階段的資料模型與操作語意；尚未實作的 P3 階段在原生 Entity／Card 顯示 unavailable 或「尚未支援」，拒絕啟用及啟動，不提供可誤認已生效的空開關。P3 再逐項開放已通過驗收的階段。

## 3. 總開關語意

### 關閉

1. 先阻擋新的整輪、單階段、外部服務、自動跟隨及重試開啟命令；所有入口使用相同後端 gate。
2. 撤銷舊任務世代，取消尚未執行的脈衝、等待、Timer、延遲及重試。已送出 I/O 不宣稱能回滾，轉入安全停止及回饋確認。
3. 只停止本槽明確擁有的輸出，完成共用輸出仲裁，不觸碰其他槽或原有外部自動化。
4. 停止過程顯示 `stopping`；輸出未確認關閉時必須保留故障／未知提示，不能只因設定已 OFF 就宣稱設備已安全停止。
5. 保留子開關、流程/星期、參數與配方。本整合不保存/刪改外部排程定義，只拒絕停用期間的控制請求且不補跑。
6. 監測、品質診斷、參數編輯及安全告警仍可使用；總開關關閉不等於卸載整合或消除故障。

### 開啟

- 只恢復「允許啟動」，不立即開啟任何馬達，不恢復被中止的加藥／等待任務，不補跑錯過的排程。
- 原子檢查當下設定、急停／故障狀態、階段可用性與必要感測器／輸出；不得自動清除急停。
- 之後明確啟動或外部 automation/排程呼叫整輪入口，且通過 gate，才可運行。
- 關閉總開關不得覆寫任何子開關；再開啟須維持原有組合。

## 4. 子開關與組合

- 啟動前依已啟用階段形成可執行集合；停用者標示 `skipped_disabled`，不是 `completed`、成功達標或故障。
- 支援全部開啟、只補水、補水＋加酸＋攪拌、只加養／加酸等組合，但每個階段仍檢查安全前提。任一組合不合法時須具體說明原因，不默默啟用被使用者關閉的階段。
- 全部子開關 OFF 時可以保留設定，但不啟動控制；顯示「未選擇任何階段」。
- **執行中停用**：立即拒絕該階段後續物理開啟並取消其工作，確認其輸出停止；不能等下一輪才生效。共用循環馬達僅在沒有其他合法所有者需要時關閉。安全相依的其他階段應停止或進入明確安全收尾，不可繼續盲目加藥。
- 執行中停用階段後，預設中止本輪的自動接續，待使用者明確重新啟動按新組合評估；不以被中止階段冒充完成。若未來要支援不中斷本輪的動態重組，須先補決策與相依圖測試，不能默認已支援。
- 執行中重新啟用子開關不自動重啟被中止工作；新請求重新驗證最新設定。

## 5. 流程編排、星期、整輪與單階段

- **啟動整輪**：按後端保存的流程 revision、子開關、各階段星期及安全條件執行。順序、重疊、相對延遲與開始/完成/感測條件由使用者配置，不硬編碼原站補水→加養→加酸。
- **啟動單階段**只執行指定階段，仍受總/子開關、實際開始前星期及安全gate約束；本次不新增忽略星期選項。
- 後端保存/執行有界 typed 依賴圖，拒絕循環、自依賴、缺參照、無入口與無上限等待；不接受任意程式碼或任意 service。重複節點/並行組界限待 R02，不能把單純排序列表當完整編排。
- 子開關 OFF 為 `skipped_disabled`，星期不符為 `skipped_weekday`。純排序可採明確略過政策；必要實際開始/完成依賴不得偽造事件，無法滿足時 `blocked_dependency`；細節待 R02。所有並行仍受最低液位、必要混合、酸/養泵限制、劑量/期限與物理資源仲裁約束。
- 四階段各自星期一至日複選，全選＝每天、空集合＝無允許日；加養不固定一二五六。星期是某次啟動的允許條件，不會自行觸發排程或等待到下個允許日。
- 已確認依HA時區，在每階段實際開始前、包含依賴/延遲/資源等待之後檢查星期，不採整輪開始日固定資格。已開始階段跨午夜不中斷，下一階段按實際開始日檢查；不提供默認手動豁免。
- 流程/星期修改建議下一輪生效、每輪綁定 revision；總/子開關關閉、急停及收緊安全上限仍即時阻擋新物理開啟。保存/版本衝突契約待 R04，未保存草稿不影響運行。
- 外部排程/HA automation 決定何時呼叫**整輪**入口。本整合不提供時刻/cron/日曆排程、排程匯入、外部腳本建立或旁支管理；混合等待/脈衝/重試/安全期限仍由後端負責。
- 原生服務須有明確且已載入的本整合 config entry 目標、權限與版本校驗，schema 先拒絕缺值/null，避免 helper 在 None 時自動選唯一槽；不默認第一槽/全部槽、不自動開 Enable；停用/急停/忙碌/重複請求及無工作結果需明示。受理不等於實際開始、完成或可灌溉，結果以 run ID/原生狀態觀察。
- 研究 `start_flow` 僅提案名，不是現有 API；正式名稱、schema、忙碌/無工作/去重期限與回應待 R04、P2 前凍結。entry 屬於 domain 不等於 caller 授權：管理員專用或受控 Entity 權限政策需明確，傳遞 call.context，合法無 user_id 的內部 automation 不一概拒絕；研究建議 SupportsResponse.OPTIONAL，僅請求回應時回 JSON 受理/run ID，否則 None，不要求外部排程讀 response。服務需原生註冊、翻譯與 selector，Card 非唯一入口。

## 6. 安全限制與備妥判定

- 關閉補水不代表允許低液位加藥；不滿足安全液位時拒絕加養／加酸，而不是擅自補水。
- 關閉「獨立／最終攪拌階段」不等於取消加藥所需最低循環、混合與採樣等待。必要混合無法滿足時拒絕加藥，明示相依原因；不得用顯示層繞過。
- 品質在區間、流程完成與允許灌溉為不同結果。略過、停用、中止、讀值過期或故障不能自行轉為養液備妥。
- 總開關是正常停用，不是緊急停止。急停為鎖定保護；復歸與重新啟動分開，開啟總開關／子開關不能解除急停。
- 即使總開關 OFF 或階段停用，與本槽相關的設備失敗／輸出仍開啟警告不能被隱藏。外部手動繼電器或其他 HA 自動化不受本整合總開關直接封鎖；遷移須消除雙重控制，並明示無法控制的外部行為。

## 7. Card 與原生前台

- 同時呈現總開關、四個子開關及有效流程預覽，不能只用顏色表示；已確認不提供獨立鏈結，增加整輪運行Switch，與服務共用啟停及狀態權威。P3 最小 UI 採可排序階段列＋開始方式/條件/相對延遲＋並行組＋星期複選與七日預覽；支援按鈕/下拉而非只靠拖曳。P5 保留進階視覺化編輯器、手機/鍵盤體驗。
- 啟用設定、啟動一次、停止本輪、緊急停止、復歸是不同控制。前台不能把 Switch toggle 當作一次性啟動。
- 顯示每階段 `disabled`／`skipped_disabled`／`skipped_weekday`／`blocked_dependency`／`waiting_resource`／`running`／`completed`／`aborted`／`fault`；停止請求與物理停止確認分開顯示。
- 保存與操作結果由後端讀回；取消 UI 編輯不得改後端；切槽、斷線、舊回應不能把操作送到另一槽。
- 原生 HA、Card、外部 automation 及服務操作共用 gate；Card 不直接呼叫底層馬達服務，不能在瀏覽器擁有流程計時器。
- P1 schema v1 與 shadow-only Card 保持不變。P2 控制能力須使用明確版本化／能力宣告，舊 Card 對未支援控制契約繼續 fail closed；不能在本次文件更新偷偷擴張已發布 P1 的可控能力。

## 8. 必要驗收案例

| 編號 | 必須驗證 |
|---|---|
| C01 | 初次設定／遷移不致動；未支援階段不可啟用 |
| C02 | 總開關 OFF 阻擋原生、Card、單階段、整輪、外部服務及跟隨等所有入口；錯目標/停用/忙碌/重複請求不誤開泵（R04） |
| C03 | 總開關 OFF 發生在脈衝／等待／重試／已排隊請求時，舊工作不能重新開輸出 |
| C04 | 關閉總開關後保留四子開關、流程/星期與配方；重啟 HA／重新開啟不續跑、不中途補藥 |
| C05 | 四子開關的每一組合都能解析，停用階段明確略過；全 OFF/星期全不允許無工作不冒充完成；必要依賴不可偽造（R02/R04） |
| C06 | 執行中關閉各階段即時中止；停止未確認必須故障可見；重新啟用不恢復舊任務 |
| C07 | 只補水、略過加養、只酸度調整等單獨與組合路徑，安全前提不足有明確拒絕 |
| C08 | 關閉獨立攪拌不能繞過加藥必需的循環／混合；共用輸出不被另一階段誤關 |
| C09 | 可配置多種順序、合法重疊、相對延遲/條件與各階段七日；非法圖/空集合/跨午夜/等待後改日/略過依賴均有結果，單階段不隱含接續（R01–R03） |
| C10 | 子階段停用／中止不等於水質合格或可灌溉 |
| C11 | 急停／復歸與總開關獨立；切換啟用不清故障、不自動開馬達 |
| C12 | 整輪Switch/服務共用後端；ON不重複啟動、OFF確認停止、外部啟動同步ON、完成自動OFF、重啟不續跑；原生與Card狀態一致，失敗保留真實狀態；雙擊、跨槽、舊回應/版本衝突不得錯寫；預覽/保存/取消不致動且草稿保留（R04） |
| C13 | 相同物理輸出之直接／定時 Entity 別名先確認對應並統一仲裁；不同槽不互相接管 |
| C14 | 外部控制或原自動化仍能干預時明確揭露；沒有將新總開關誇稱原站全域急停 |

C01–C04、C06、C11–C14 先由 P2 奠定與補水驗證；涉及加養／加酸／混合的 C05–C10 在 P3 完整驗收；外部 action/結果、配方、通知與品質/許可互通在 P4 驗收，不以排程遷移或旁支管理作門檻。新增控制不得改動原農場，除非另外取得明確部署／接管授權。
