# P4b 現行品質／完成／許可契約

狀態（2026-11-05）：F4來源已實作，獨立SPEC與完整品質兩審通過，本機隔離驗證完成；出版等價/exact-index/新commit hosted CI待驗，非部署或實機驗收。唯一選案：**獨立 quality_v1 API + 原生品質 sensor + 唯讀 permit binary_sensor**；不採 status schema6。control_contract_version=5、S1–S5、recipe_v1 DTO 與所有既有服務 wire 均不改。舊 shadow 與 control ready_for_irrigation 仍 false，意指該舊介面從不授權；新介面明標「P4b 唯一許可權威」。不能在 S5 加 quality 欄位，strict Card 會拒絕全部。

## 已知來源與缺口
- manager.snapshot 固定 schema1/shadow/ready=false；sensor.ControlStatus 以此為 base，p3c_projection.snapshot_v5 經 v4 衍生，沒有覆寫 ready。Card validV4 明確要求 false；validV5 用明確投影再驗 validV4。
- flow.run 的 all(records.result) 即 outcome=completed，包含 skip/blocked；不能把 flow_state=completed 當資格。records 有 result/started_at/settled_at，run_plan 有 run_id/settings_revision/flow_plan_revision/enabled_stages。
- nutrient.sample_token 已支援 reported/sequence/timestamp；reported 須事件證明，snapshot 每5秒刷新不是新樣本。現有控制有 state_changed + filtered state_reported；不能用 getter 增加 count。
- write_settings 為 Tank.lock 下同步 commit；Number、recipe Apply 共用；recipe Save/Cancel 不套用參數。recipes.execute 是可復用的 ACL-before-lookup / lock-after-reauthorize 結構。

## 持久設定（exact shape 見 API_SCHEMA.json）
entry.options 新增 quality_policy={schema_version:1,revision:N,enabled:false,stable_samples:8,stable_interval_seconds:300,stable_duration_seconds:2100,permit_ttl_seconds:300,required_stages:[refill,nutrient,acid,mix],sources:{ph/ec/level:{mode:reported,attribute:null,report_contract_confirmed:false}}}。
缺 namespace 時讀出上述虛擬預設 revision0；不自動保存、不升舊 entry；只有 control_contract_version=5 可保存啟用，舊1–4僅顯示 disabled/unsupported。schema 未知 fail closed，不能重設成 v1。

預設依據：enabled=false/confirmed=false 是新工程 opt-in；8與300復用 dosing_settings.DEFAULTS 的 stable_samples/stable_interval_seconds，不宣稱是通用設備安全值；duration=(8−1)*300 為新工程穩定跨度；首次虛擬 policy 的 TTL 從既有 max_age_seconds（無值300）取值並限制1–86400，保存後固定；不是另猜原HA期限。required_stages 四列是保守完整輪工程預設，可由原生／Card 明確選擇非空子集。reported/null 只是停用表單初值，不表示來源已能證明新實測。所有新 policy 欄位都可前台調；schema/revision 唯讀。
不新增品質上下限：直接用現有10 Numbers 的 ph_low/high、ec_low/high、level_low/high（含端點）。有效期只用既有 max_age_seconds；來源須有限、單位合約正確、未 unknown/unavailable/移除/禁用、時間非未來。危險值仍是既有 safety_parameters（3.8/1.3/6.8及600s已定，不複製），不修改控制／告警語義，不以高pH延遲當品質豁免。新策略啟用需三來源 report_contract_confirmed=true；timestamp/sequence 模式必明填 attribute，不猜設備安全值或報告能力。

## 三真值
quality.state = disabled/unsupported/invalid/out_of_range/stabilizing/qualified，單純反映資料品質，可在無 run 下 qualified。
completion = none/running/completed/incomplete/aborted/fault，描述本載入 epoch 的最新整輪 receipt，非歷史成功。
permit.granted 僅在以下全成立的一次候選上由 false→true：
1. policy enabled、entry loaded/active/not disabled、master ON、fault=null、所有必要 capability 仍有效。
2. 新 S5 整輪 run_plan 存在且 run_id 對應當前 admission，並非單階段入口；controller generation 與 snapshot revision fence 相符。
3. outcome=completed、flow.active=false、非stopping；所有 required_stages 在 accepted run 中 enabled 且 result=completed；任何 skipped_weekday/blocked_dependency/aborted/fault 都拒絕本輪。非 required 且 accepted-disabled 的 skipped_disabled 可存在，但不冒充成功。required disabled 必拒絕；至少一個 required stage.started_at 非 null（實際 dispatch），全skip、全no-op、nullrun 無資格。未實際投藥但已在目標可完成該 stage，不偽造 dispatch。
4. 全 stages owns_io=false、operations 無 pending、controller on_task/off_task 已 settled、late_on=false、leases 空、所有本槽已綁定輸出實際 OFF（unknown/失去映射也拒絕）。用公開閉合投影，不能修改或放鬆 P3 loops。
5. terminal closure 之後重新收集完整品質穩定窗口，三來源都符合目前區間與有效性；不拿 run 前／投藥中樣本充數。
此選擇允許明確配置 required 子集合，但不因停用或 skip 自行合格；parent 需一次確認此工程政策，而非向 user 詢問 DTO。

## 新實測、穩定與唯一時鐘
每槽 QualityCoordinator 獨立 runtime epoch UUID、單調 observation_revision、latest source token。只在 filtered state_reported／state_changed 事件接受樣本；reported 僅 state_reported 或真正值改變，token=last_reported；sequence 嚴格 int>=0且前進；timestamp aware ISO且 age合法且嚴格前進。配置確認是上游實測語義承諾，不保證硬體本身未重播。snapshot polling、重複事件、同 token、延遲 token 絕不增加次數。
一次穩定 round 要三來源 token 各比上次已消費 round 前進，且最短 stable_interval_seconds 已過；每個 round 只消費當下三個 token。先於 interval 的樣本可更新 pending 最新值但不計次；timer 不會創造 round。count>=stable_samples 且 first_round 到目前 round 的 monotonic 跨度>=stable_duration_seconds 才 qualified。任一invalid/out-of-range/倒退seq/來源移除先即時清count與candidate；seq回繞須明確重設來源／重載且新run，不能當新資料。來源重建／綁定變更遞增 epoch fence。所有門檻後端單調時鐘決定；UTC只顯示。
expiry deadline = min(grant_mono+permit_ttl_seconds, 三來源 last_reported freshness截止, timestamp模式的source timestamp截止)。用可取消 monotonic call_at 精確排最早 deadline；不是5秒poll才撤銷。源新事件可延展 freshness分量但不可延展 grant+TTL 硬截止；getter/API再次檢查 now>=deadline 即 false。計時器延遲受HA event loop調度限制，不能宣稱硬即時物理保護。UTC expires_at 只作同一 deadline 的顯示，不供Card授權。

## 撤銷與編輯矩陣
任何出界、過期、故障、急停、abort/stop、masterOFF、必要子開關OFF、capability/registry變動、輸出非OFF/pendingON、new run/單階段啟動、entry disabled/unload/shutdown：先同步撤銷當前 permit，清候選並標記 consumed。恢復來源、reset fault、enableON 不復活；必須新整輪成功。品質可以獨立重新變 qualified。
quality Save（含同值）是明確重新配置：CAS成功後 revision+1、撤銷、清窗口／候選；不start、不清fault。Cancel/未保存草稿/拒絕CAS 不寫不撤銷。既有 settings/Number 實際變動、來源/freshness/commissioning變動、flow plan實際保存、recipe Apply 成功（即便同值）都撤銷並要求新run；recipe catalog Save/Delete、僅選擇、Cancel 不撤銷。同值普通Number不另改既有語義。settings變動於commit前同步invalidate，不等 options listener。Apply同值用明確 provenance hook，不能改 recipe_v1 wire。
permit True、receipt candidate、count 不持久化／不RestoreEntity。startup=false、completion=none，即便persist fault仍在也不清。unload先invalidate再shutdown；卸載失敗也不恢復oldpermit。移除所有timer/bus/listener；reload建立新epoch，late callbacks / old RPC不得改新槽。

## API、ACL 與原生入口
提案服務 domain uninus_nutriculture：get_quality_v1（SupportsResponse.ONLY）、save_quality_policy_v1（OPTIONAL）；標準call_service return_response=true，回應由HA service_response包DTO。read payload exact {config_entry_id}；write exact {config_entry_id,expected_policy_revision,expected_settings_revision,expected_flow_plan_revision,policy}。policy不得含schema/revision，與API_SCHEMA一致。unknown/null/bool當int/NaN全部拒絕，revision<=2^53−1。無 manual grant/revoke/fault-clear API。
沿recipes.authorize政策：所有新API需active非system_generated真人admin context，先授權再lookup；lock後再await授權，並重驗entry identity/domain/loaded/not disabled/runtime/active/control version/CAS，直到同步commit不得再await。保留內部控制automation既有ACL，不改為此新管理ACL。原生Options開 quality editor 不保存主頁，Save走相同transaction（Options本身管理員入口），Cancel零寫；採 HA 原生 selector表單，不逼貼JSON。所有新policy可在原生前台編輯，無須Card；不新增可寫permit Switch。
新增唯一 IDs :quality_status、:irrigation_permit（entry_id前綴）；quality sensor state如上、attributes就是QualityDTO v1（另許HA metadata）；binary sensor is_on=同coordinator permit.granted，attrs exact {schema_version:1,config_entry_id,epoch,observation_revision,run_id,expires_at,reasons}。Registry可改名，API.entities回實際ID或null，禁止猜名稱，不能依name或第一槽匹配。
