# P5c 重要運行／事件時間軸UI契約

> 已完成隔離整合、獨立SPEC與品質安全兩審；來源出版與精確提交CI分別按實際結果核驗。不代表已實機／HACS驗收。


## 操作入口與真值

1. Card選取實際schema5控制狀態sensor；四階段卡使用已受理本輪計畫，沒有運行時明示已儲存計畫。草稿、請求重疊、實際開始／結束與HA觀測輸出分開；unknown不等於OFF。
2. 展開「已記錄運行事件（Recorder）」才讀取；選1／6／24小時、來源篩選、上／下一頁或重新整理。每頁最多50筆呈現，完整保留結果不因換頁刪除。摘要區分觀測事件、窗口基線與資料缺口。
3. 可選quality_entity／result_entity必須明確選同槽實體；未配置、無可讀資料或權限篩選皆明示，不借目前值補歷史。歷史許可不改變現在的品質／許可；停止原因只取實際後端記錄。
4. 切槽、身分或連線改變會清除舊事件；讀取被拒後不自行重送。改顯示時區不重設同身分的拒絕狀態，且已有事件時間可重新顯示而不查詢。

已驗證隔離原生Core／Recorder／假硬體與真Chromium操作，不是完整HA宿主、物理感測／OFF回饋或24小時保留保證。重要UI之後才確認指定實機、可致動範圍與停止條件；不讀現場認證或連原站。選配診斷、完整多槽／HACS／備份與發行仍保留。

## 工程接受契約

C01. Existing S5 status validity remains required. Runtime panel [data-runtime-panel] visible ahead of long settings, with [data-runtime-stage="refill|nutrient|acid|mix"] four stable nodes. Use accepted run_plan order/revisions during a run, otherwise saved flow_plan explicitly labelled not an active run. Never use dirty draft for actual graph.
C02. Distinct localized state labels AND literal codes for idle, disabled/skipped_disabled, skipped_weekday, blocked_dependency, waiting_delay, waiting_condition, waiting_resource, running/phase, completed, aborted, fault and stopping/confirming_off. Show waiting_reason, actual started_at/settled_at if present; missing is unknown/not started, never zero or estimated arrival. More than one running stage displays simultaneously; no fake serial progress percentage/animation.
C03. [data-runtime-output="refill|nutrient|acid|circulation"] on/off/unknown sourced only from output_states. Label as HA observed output, not physical flow/arrival/OFF-proof. Stopping/confirming-off and unknown/fault are prominent warning, never a fabricated completed/OFF. Show flow state/run ID/revision and available fault reasons. Existing Stop/emergency/reset controls remain real unchanged semantic calls; no new actuator controls.
C04. Runtime states are informational, not quality/irrigation authorization. No fixed claim that all versions lack new quality permit; when mentioning permit explicitly refer to independent quality_v1 authoritative UI. Keep sensor values, settings and existing safety behavior unchanged.
C05. Recorder trace panel [data-trace-panel] details, closed by default; [data-trace-toggle] summary, [data-trace-window]1/6/24 hours, [data-trace-refresh] explicit refresh, [data-trace-status]/[data-trace-error], [data-trace-list] chronological events. Existing History panel remains separately operable. No polling/background query while closed; opening/window/explicit refresh bounded read. Keyboard page/filter controls accessible. Per-page<=50 events with total/page count and no silent dropping; full decoded changes retained within safety bounds.
C06. Trace queries existing history/history_during_period with include_start_time_state=true, significant_changes_only=false, minimal_response=false,no_attributes=false. entity_ids only explicit config.entity, and configured valid same-entry quality_entity/result_entity. No guessed IDs, no all-entity history, no raw outputs/services. Optional invalid/missing/mismatched source omitted with explicit notice; status valid required. Maximum10000 rows/source, total30000,20-second read timeout; malformed/oversized data fails visibly, never truncates silently.
C07. Strictly validate historical source DTO before selecting allowlisted fields. Decode native compressed s/a/lu/(lc) rows; reject unknown entity keys. Sort timestamps (Unix seconds converted once), same-time last row per entity wins; latest pre-window row is labelled baseline at window start, NOT new event/start/measurement. Later changed stage/phase/result/wait/output/permit/run state and available stop/fault reason become observed transitions with HA timezone+offset, run/epoch identity where supplied. Do not join across run/epoch/invalid gaps; invalid/unavailable rows become explicit data gaps, never carried as current truth. Recorder attribute snapshots do not prove exact physical switching time or complete event audit; disclose retention/exclusion/readfilter/entity-reuse limits and no current value substitution.
C08. Optional quality DTO filtered through existing strict validator and same config_entry_id; historical granted=True is labelled HISTORICAL ONLY, never changes live permit/controls. Optional ResultDTO validated with existing resultDTO; observed last_result/current_run/latest_event allowlisted fields expose stable terminal stop reasons when available, not invented reasons. Missing optional sources explicitly explain unavailable permit/result history while valid stage/output history remains usable.
C09. Purge runtime stale authoritative display/trace cache on disconnect, reconfigure/entry/principal/role/active/transport changes. Never accept late replies of old owner or closed details (check .open at acceptance independent of delayed toggle), purge and latch read denial within current owner. No unauthorized/admin fallback, no auto-mutation/retry. At most one active trace transport per scope; timeout may release UI wait but cannot allow stale response acceptance. Same-context hass telemetry preserves controls/focus/scroll/drafts/expanded state and must not refetch trace or recreate runtime nodes.
C10. Real Chromium at card widths320/360/768/1280, narrow-short and narrow-tall, dark/light. Zero horizontal container overflow, min44px new interactive controls, keyboard open/time window/refresh/page/filter and unchanged Start/Stop/editor route. Two same-name synthetic slots with distinct stable entity/entry IDs and delayed reply isolation; not labelled full commissioned multislots or physical acceptance.
C11. TDD one behavioral tracer at a time: new test fails on actual absent user-visible runtime/trace behavior, keep exact source/test raw RED/GREEN and real child exit; then edge/race coverage. Old tests remain permanent. Register new module in canonical tests/check.py+workflow with actual AST/executed count, not invented totals. Run existing14unit/99DOM/16history and new module on integrated candidate; keep non-overlapping totals separate.
C12. Integrated native proof uses real Core/Auth/Recorder/registered History, synthetic hardware only. New browser child is invoked on integrated candidate (explicit CARD_PYTHON and CHROMIUM_EXECUTABLE), route actual shipping trace query to native registered handler; confirm timeline status/output + optional quality/result recorded data, permissions filtered/missing, zero browser mutations, clean Core/Recorder shutdown. Native runner without new UI may report SETUP_READY / desired-behavior RED, never fake GREEN. Reuse existing fixture plumbing but no arbitrary SDK patching or raw fixture responses passed off as native.
